# User journey review

Scope: account access, private work, shared infrastructure, custom environments and the Gallery. This distinguishes implemented APIs from a guided product experience. It is not a public SaaS certification.

## Observed behavior

- Local first setup creates the administrator. The login screen also offers ordinary account registration when enabled; the production setup-status endpoint reported registration enabled during this review. The Hostinger template uses the native account/session through Traefik. The separate local Caddy deployment also has an outer HTTP-auth gate.
- Ordinary users have private native threads, project files, Agent definitions, skill choices, environment preferences and learning data. Ownership is enforced at API/storage boundaries; the administrator's role is not an automatic thread-owner bypass.
- Community mode uses administrator-managed coordinator/team models and provider credentials. Hosted preview uses encrypted private DeepSeek/OpenAI-compatible account profiles; it does not offer the same personal Codex/Antigravity login journey. Organizations with shared membership and invitation flows are not implemented.
- Runtime images, preparation cache, CPU/RAM admission, default program versions and the instance Gallery are shared infrastructure. Reusing software does not reuse another assignment's writable staging or its project data. Ordinary users cannot change global resources, shared credentials, approved registries or import software images.
- Users can create a native environment from a preset or from purpose/instructions/skills, select demand/preload behavior, prepare it, inspect progress, clone it, edit it and export its native configuration. Prepared software export includes an image and rebuild recipe; trusted image import remains administrator-only.
- A terminal opens a separate disposable container. Shell edits and ad-hoc installations do **not** update the prepared environment or become a reproducible recipe. Closing/expiry removes that container. There is no guided “capture this successful experiment as an environment update” flow.
- The Gallery can activate managed packs as native skills or environment configurations. Publication is versioned and publisher-owned, and new publications are unverified. The interface currently requires a manually authored JSON manifest. Exporting a native environment is not the same operation or format as publishing a Gallery pack.
- Publication shares a manifest with users of this installation. There is no automatic upload to a public global Hub. Administrator-configured pinned remote catalogs can be synchronized and catalog JSON can be exported.

## Main usability gaps, ordered by impact

1. **First usable task.** A new Community account needs a clear read-only readiness summary for the administrator-managed model connection, with an actionable message when unavailable. The current onboarding ignores a 403 from the administrator-only catalog; the user can reach a task without knowing why execution is unavailable. Hosted preview configures private models from a different page. Explain the deployment mode and account responsibility before asking for credentials.
2. **Outcome-led environment creation.** Purpose, skill selection and preload controls exist, but the user must already understand tools, dependencies and execution profiles. Guide the user through outcome → recommended editable setup → resource impact → representative test → save. Clarify that preparing software is optional for starting a general task.
3. **Environment versus agent scope.** The current environment card opens an Agent-scoped chat. That restricts the available skills to its profile; it is not equivalent to a general project freely composing roles across every enabled environment. Label the restriction explicitly and offer a general-project path.
4. **Improve without losing a working setup.** Configuration edits, cloning, verified program versions and separate variants exist. There is no integrated personal environment release history with change comparison, a user-defined acceptance fixture and one-click promotion/rollback of a complete configuration. Terminal experiments are ephemeral and need an explicit source/recipe capture mechanism rather than an implicit container commit.
5. **Publish from a working environment.** Add an environment-to-pack wizard: choose reusable purpose/skills, sanitize private instructions and paths, include actual test/compatibility evidence, preview English/Italian metadata, then submit a version. Keep configuration/recipe publication separate from large software-image transfer and project delivery.
6. **Private, instance and public scopes.** Show ownership and sharing scope before publication. Add draft/submitted/reviewed states and administrator moderation, rather than equating a valid JSON manifest or an activation with trust. Public hosting and publisher signatures remain separate work.
7. **Account administration.** Current UI lists and suspends/restores accounts; role assignment is an operator/API action. Invitations, verified email, account recovery and organization membership need a coherent product flow. Open registration plus shared paid Community credentials should be an explicit administrator choice with visible consumption/admission controls.
8. **One operational vocabulary.** Present purpose, capabilities, working projects, retained sources, preparation/update reasons and actual missing checks. Put image identifiers, native commands and detailed layers in diagnostics. Finish English/Italian coverage rather than mixing translated navigation with Italian operational forms.

## Responsibility boundary to preserve

Users own their tasks, files, private methods, selected capabilities, custom environment configuration and publication proposals. Administrators own identity/access policy, allowed tools/versions and provider hosts, Community shared connections, global capacity, trusted image imports, registry distribution and moderation. Neither software cache reuse nor shared infrastructure should implicitly publish private lessons, files or credentials.

Recommended next product increment: deliver one complete ordinary-user journey with a separate administrator account, covering registration/access, first task, a custom environment, a failed representative test, a corrected variant, export and an explicitly reviewed Gallery publication. Test cross-account isolation and queue behavior at each handoff, instead of testing disconnected pages only.
